本项目是一个基于 MongoDB 的问卷系统。第一阶段完成了账号、问卷创建与填写、答案校验、条件跳转和统计等功能。第二阶段主要解决题目重复使用和修改的问题，增加了题库、共享、版本管理和跨问卷统计。

## 一 功能介绍

第一阶段支持用户注册登录、创建问卷、设置截止时间、条件跳转和查看统计。填写问卷的人需要先登录。选择匿名填写时，回答中不保存填写者账号，但系统仍通过账号生成的 HMAC 标识限制重复提交。

原来的题目只保存在各自的问卷中。同一道题放进多份问卷时，需要重复创建，后续也不方便统一查看。第二阶段将题目单独保存，每次修改都留下新版本，问卷再选用其中一个版本。

| 变更要求 | 实现方式 | 页面入口 |
|---|---|---|
| 保存常用题目 | 题目单独保存，问卷中新建题也自动进入默认题库 | 题目库、新建题目 |
| 多问卷复用 | 不同问卷可以使用同一版本的题目 | 编辑问卷、从题库选题 |
| 共享给其他用户 | 按用户名共享或开放给所有登录用户 | 题目详情、共享设置 |
| 修改不影响旧问卷 | 修改时另存新版本，问卷保留原内容副本 | 创建新版本、发布锁定 |
| 查看历史与来源 | 展示版本号、父版本、恢复来源和复制来源 | 题目详情、历史版本 |
| 恢复旧版本 | 根据旧内容生成新版本，保留全部历史 | 恢复此版本为新版本 |
| 不同版本同时存在 | 草稿手动选择版本，已有问卷不自动更新 | 选用此版本、切换版本 |
| 查看使用位置 | 按版本列出引用的问卷、题号与状态 | 题目详情、使用位置 |
| 题库管理 | 创建、改名、修改说明、加入、移出和删除分类 | 管理题库 |
| 跨问卷统计 | 同一版本跨问卷聚合，不同版本分别展示 | 题目跨问卷统计 |

## 三 数据库设计

数据库由原先的 users、surveys、responses 三个集合扩展为六个集合。

### 3.1 用户、问卷与回答

users 保存用户名和 scrypt 密码哈希。surveys 保存问卷设置和实际选用的题目快照。responses 保存问卷 ID、答案和实际访问路径，匿名回答的 respondent_id 为 null。

问卷中的每一道题保留自己的本地题号，同时增加以下来源字段：

```javascript
{
  _id: "问卷内部题目ID",
  prompt: "你的年龄（周岁）",
  type: "number",
  required: true,
  options: [],
  validation: {min_value: 0, max_value: 120, integer_only: true},
  order: 0,
  jump_rules: [],
  source_question_id: ObjectId,
  source_version_id: ObjectId,
  source_version: 1
}
```

问卷中保存一份题目内容、选项和校验规则的副本，也就是题目快照。source_question_id 表示题目系列，source_version_id 表示选用的版本。答案仍然按问卷内部的题目 ID 保存，所以不需要修改旧回答。

### 3.2 题目系列 question_series

```javascript
{
  _id: ObjectId,
  owner_id: ObjectId,
  latest_version_id: ObjectId,
  latest_version: 3,
  next_version: 3,
  shared_with: [ObjectId],
  is_public: false,
  created_at: Date,
  updated_at: Date,
  legacy_key: "旧问卷ID:旧题目ID" // 仅迁移记录具有此字段
}
```

question_series 保存题目的作者、共享对象和最新版本。题库列表显示最新版本，旧问卷仍用原来的内容。

### 3.3 不可变版本 question_versions

```javascript
{
  _id: ObjectId,
  series_id: ObjectId,
  version: 3,
  parent_version_id: ObjectId,
  restored_from_id: ObjectId,
  forked_from_id: ObjectId,
  prompt: String,
  type: "single" | "multiple" | "text" | "number",
  required: Boolean,
  options: [String],
  validation: Object,
  created_at: Date
}
```

每次修改插入一条新文档，不更新旧版本的题目内容。parent_version_id 记录直接来源；restored_from_id 记录恢复的历史版本；复制他人题目时 forked_from_id 记录原始版本，新副本由复制者独立拥有。

### 3.4 题库 question_banks

```javascript
{
  _id: ObjectId,
  owner_id: ObjectId,
  name: "人口信息",
  description: "常用人口统计题",
  question_ids: [ObjectId],
  created_at: Date
}
```

题库保存题目系列的 ID，同一道题的不同版本放在一起管理。列表显示最新版本，详情中可以选择旧版本。删除题库或移出题目只改变分类，不会删除题目版本、问卷和回答。

### 3.5 索引

| 集合 | 主要索引 | 用途 |
|---|---|---|
| users | username 唯一 | 防止重复账号 |
| surveys | public_id 唯一、owner_id 与 created_at | 公开链接及个人问卷列表 |
| surveys | questions.source_version_id | 查找版本的使用位置 |
| responses | survey_id 与 submitted_at | 问卷统计与回答查询 |
| responses | survey_id 与 single_submission_key 条件唯一 | 并发情况下限制重复提交 |
| question_series | owner_id 与 updated_at、shared_with | 个人题目与共享查询 |
| question_series | legacy_key 条件唯一 | 防止旧数据重复迁移 |
| question_versions | series_id 与 version 唯一 | 版本顺序和并发版本编号 |
| question_banks | owner_id 与 name 唯一 | 同一用户题库名称去重 |

## 四 版本管理

### 4.1 修改与并存

创建新版本时，可以从任意历史版本开始修改。例如已有 v1 和 v2，也可以再从 v1 修改得到 v3。不同问卷分别选用 v1、v2 或 v3，各自保留原来的版本。

版本号通过 MongoDB 的原子计数器分配，并设置唯一索引。同时保存多个版本时，最新版本号只向更大的编号更新，避免较晚完成的旧操作把版本号改回去。

### 4.2 恢复旧版本

如果当前是 v2，恢复 v1 后会生成 v3。v3 使用 v1 的内容，父版本记录为 v2，restored_from_id 记录为 v1。这样既能恢复旧内容，也能保留 v2 和整个修改过程。已有问卷仍使用原来选定的版本。

### 4.3 发布后锁定

问卷发布后，添加题目、删除题目、增删跳转规则和切换版本均被服务端拒绝。关闭后的问卷同样锁定；界面隐藏相应编辑入口。

修改题目的数据库操作中也检查草稿状态，避免问卷刚发布，另一个修改请求还在继续写入。已发布问卷需要修改时，先复制成新草稿，再选用新版本。

### 4.4 草稿切换版本

草稿中的题目可以切换到同系列的其他可用版本，保留问卷内部题号和顺序。切换后清空本题的跳转条件，提示创建者重新确认；其他题目跳入该题的目标仍有效。

### 4.5 复制问卷

复制生成新的草稿和访问链接，不复制回答，不继承发布状态。题目内部 ID 重新生成，跳转目标同步映射到新题号，版本来源保持不变。

## 五 共享与统计权限

题目作者可以按用户名共享，也可以允许所有登录用户选用。被共享者可以选用各版本，或复制为自己的独立题目后修改，不能修改原题的版本、共享设置或其他用户的题库。

题目作者可以查看该题被哪些问卷使用，以及这些问卷中该题的匿名统计。收到共享的用户只能查看自己问卷中的回答。共享页面会说明统计范围，统计结果不显示填写者账号，也不允许访问他人的其他题目或问卷编辑页面。

取消共享只阻止后续访问和选用，不删除已经加入问卷的快照。因此他人已完成的问卷仍可以正常填写和统计。

## 六 统计方法

除了原来的整份问卷统计，还可以从题目详情查看跨问卷统计。统计时先找出使用某一版本的问卷，再按“问卷 ID 和该问卷中的题目 ID”找到答案，最后通过 MongoDB 聚合计算。

查询必须匹配这两个字段的组合，不能把所有问卷 ID 和所有题号分别拼接，否则可能将另一份问卷中同名题号的无关答案混入统计。

| 题型 | 统计结果 |
|---|---|
| 单选 | 每个选项次数，包含未被选择的选项 |
| 多选 | 拆分数组后分别累计各选项次数 |
| 文本 | 展示相应题目版本的全部文本回答 |
| 数字 | 回答数、平均值、最小值、最大值、各数值出现次数及全部数值 |

不同版本分别统计。例如“年龄（周岁）”与“年龄（月）”不能直接混算；查看全部版本时，也展示独立的版本统计卡片。

回答数按实际保存的答案条数计算。同一个人在不同问卷中回答了同一道题，或者同一版本在一份问卷中出现多次，都会分别计入，不按账号合并。

## 七 第一阶段数据迁移

应用启动时，会为第一阶段没有版本信息的题目建立题目系列和 v1 版本，并放入作者的默认题库。

迁移只增加来源字段，原题干、选项、规则、题号、问卷状态和回答保持不变。每道旧题目用“问卷 ID:题目 ID”作迁移标记，重复启动不会生成重复版本。原来分别创建的题目即使题干相同，也不会自动合并，以免把含义不同的题目放在一起统计。

## 八 启动与使用

### 8.1 启动

第二阶段没有增加新的第三方库。在项目目录中执行：

```powershell
python -m pip install -r requirements.txt
python run.py
```

运行前需要先启动 MongoDB，以下路径按本机安装位置修改：

```powershell
& "D:\mongo\bin\mongod.exe" --dbpath "D:\mongo\data\db"
```

浏览器打开 http://127.0.0.1:8000。默认数据库为 survey_system，连接配置保存在 .env 中，首次运行可由 env.example 复制生成。gitignore.txt 是忽略规则模板，复制为 .gitignore 后生效。

### 8.2 题库操作流程

1. 登录后点击顶部“题目库”或“管理题库”。
2. 新建题库分类，再创建单选、多选、文本或数字题。
3. 在题目详情中设置共享用户名。
4. 编辑草稿问卷，通过“从题库选题”选择需要的版本。
5. 需要改题时点击“基于此版本修改”，保存为新版本。
6. 在历史列表中查看父版本、恢复来源和使用位置。
7. 使用“恢复此版本为新版本”恢复内容；旧问卷继续使用原版本。
8. 点击“跨问卷统计”，查看不同问卷中的同一版本回答。

## 十一 不足与改进

1. 题目只能跳转到后续题目，跳转规则需要在每份问卷中单独设置。
2. 不同版本的答案目前分别统计。如果以后要合并不同单位的数据，还需要增加换算规则。
3. 题库目前支持基本分类，题目数量较多时，可以继续增加分页、标签和排序功能。
