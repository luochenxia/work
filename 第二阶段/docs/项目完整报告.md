## 一 项目功能与需求对应

第一阶段支持用户注册登录、创建与管理问卷、设置截止时间、动态条件跳转和结果统计。所有填写者均须登录；匿名表示回答不保存可展示的填写者身份，重复提交通过基于登录账号的 HMAC 键限制。

第二阶段针对原有“题目只保存在问卷内部、不便重复使用”的问题，将题目系列、不可变版本与问卷选题实例分开管理。

| 变更要求 | 实现方式 | 页面入口 |
|---|---|---|
| 保存常用题目 | 题目单独保存，问卷中新建题也自动进入默认题库 | 题目库、新建题目 |
| 多问卷复用 | 不同问卷选用同一个明确的版本 | 编辑问卷、从题库选题 |
| 共享给其他用户 | 按用户名共享或开放给所有登录用户 | 题目详情、共享设置 |
| 修改不影响旧问卷 | 版本内容不可原地修改，问卷保存固定快照 | 创建新版本、发布锁定 |
| 查看历史与来源 | 展示版本号、父版本、恢复来源和复制来源 | 题目详情、历史版本 |
| 恢复旧版本 | 根据旧内容生成新版本，保留全部历史 | 恢复此版本为新版本 |
| 不同版本同时存在 | 草稿显式选择版本，不自动跟随最新版本 | 选用此版本、切换版本 |
| 查看使用位置 | 按版本列出引用的问卷、题号与状态 | 题目详情、使用位置 |
| 题库管理 | 创建、改名、修改说明、加入、移出和删除分类 | 管理题库 |
| 跨问卷统计 | 同一版本跨问卷聚合，不同版本分别展示 | 题目跨问卷统计 |

## 二 技术结构与兼容方式

后端继续使用 Python、FastAPI、PyMongo 和 Jinja2；前端使用 HTML、CSS 和原生 JavaScript；数据库仍使用 MongoDB。第二阶段没有引入新的第三方依赖。

核心代码分工如下：

| 文件 | 职责 |
|---|---|
| app/main.py | 原有账号、问卷、填写、发布和统计路由，以及发布后题目锁定 |
| app/domain.py | 答案校验、跳转和实际访问路径计算 |
| app/catalog.py | 题目、不可变版本、题库、共享权限、快照和旧数据迁移 |

| tests/ | 第一阶段回归测试、题目版本单元测试和真实 MongoDB 集成测试 |

原有问卷结构和答案字段保留。系统通过增加来源元数据完成升级，而不是删除重建问卷、替换数据库或重新收集回答。

## 三 数据库设计

数据库由原先的 users、surveys、responses 三个集合扩展为六个集合。

### 3.1 用户 问卷与回答

users 保存用户名和 scrypt 密码哈希。surveys 保存问卷设置和实际选用的题目快照。responses 保存问卷 ID、答案和实际访问路径，匿名回答的 respondent_id 为 null。

问卷中的每一道题保留自己的本地题号，同时增加以下来源字段：

```javascript
{
  _id: "问卷内部题目ID",
  prompt: "你的年龄（周岁）",
  type: "number",
  required: true,
  options: [],
  validation: {min_value: 0, max_value: 120, integer_only: true},
  order: 0,
  jump_rules: [],
  source_question_id: ObjectId,
  source_version_id: ObjectId,
  source_version: 1
}
```

题目内容、选项和校验规则复制到问卷快照；source_question_id 标识题目系列，source_version_id 标识固定版本。答案仍以问卷内部题目 ID 关联，旧回答无需改写。

### 3.2 题目系列 question_series

```javascript
{
  _id: ObjectId,
  owner_id: ObjectId,
  latest_version_id: ObjectId,
  latest_version: 3,
  next_version: 3,
  shared_with: [ObjectId],
  is_public: false,
  created_at: Date,
  updated_at: Date,
  legacy_key: "旧问卷ID:旧题目ID" // 仅迁移记录具有此字段
}
```

系列承载所有权和共享设置，最新版本指针用于题库列表展示。已有问卷不通过该指针读取题目，因此最新版本变化不会影响旧问卷。

### 3.3 不可变版本 question_versions

```javascript
{
  _id: ObjectId,
  series_id: ObjectId,
  version: 3,
  parent_version_id: ObjectId,
  restored_from_id: ObjectId,
  forked_from_id: ObjectId,
  prompt: String,
  type: "single" | "multiple" | "text" | "number",
  required: Boolean,
  options: [String],
  validation: Object,
  created_at: Date
}
```

每次修改插入一条新文档，不更新旧版本的题目内容。parent_version_id 记录直接来源；restored_from_id 记录恢复的历史版本；复制他人题目时 forked_from_id 记录原始版本，新副本由复制者独立拥有。

### 3.4 题库 question_banks

```javascript
{
  _id: ObjectId,
  owner_id: ObjectId,
  name: "人口信息",
  description: "常用人口统计题",
  question_ids: [ObjectId],
  created_at: Date
}
```

题库引用题目系列，而非只引用一个版本。题库列表展示最新版本，进入详情后可以选用旧版本。删除题库仅删除分类，移出题目也不会删除版本、问卷或回答。

### 3.5 索引

| 集合 | 主要索引 | 用途 |
|---|---|---|
| users | username 唯一 | 防止重复账号 |
| surveys | public_id 唯一、owner_id 与 created_at | 公开链接及个人问卷列表 |
| surveys | questions.source_version_id | 查找版本的使用位置 |
| responses | survey_id 与 submitted_at | 问卷统计与回答查询 |
| responses | survey_id 与 single_submission_key 条件唯一 | 并发情况下限制重复提交 |
| question_series | owner_id 与 updated_at、shared_with | 个人题目与共享查询 |
| question_series | legacy_key 条件唯一 | 防止旧数据重复迁移 |
| question_versions | series_id 与 version 唯一 | 版本顺序和并发版本编号 |
| question_banks | owner_id 与 name 唯一 | 同一用户题库名称去重 |

## 四 版本与快照的关键规则

### 4.1 修改与并存

创建新版本时可以选择任意历史版本作为来源，形成版本分支。例如 v3 可以直接从 v1 修改。不同问卷可以分别使用 v1、v2 或 v3，互不替换。

版本编号通过 MongoDB 原子计数器分配，并使用唯一索引约束。并发写入时，最新版本指针只向更大的版本号更新，避免较慢的写入覆盖较新的指针。

### 4.2 恢复旧版本

如果当前是 v2，恢复 v1 会生成 v3：v3 的内容来自 v1，父版本指向 v2，并明确记录 restored_from_id 为 v1。恢复操作不会删除 v2，也不会将所有问卷强制切换到 v1。

### 4.3 发布后锁定

问卷发布后，添加题目、删除题目、增删跳转规则和切换版本均被服务端拒绝。关闭后的问卷同样锁定；界面隐藏相应编辑入口。

相关写入同时包含草稿状态条件，防止“检查时仍为草稿，写入前已经发布”的竞争情况。需要修改已发布问卷时，可复制为新草稿，再明确选择新版本。

### 4.4 草稿切换版本

草稿中的题目可以切换到同系列的其他可用版本，保留问卷内部题号和顺序。切换后清空本题的跳转条件，提示创建者重新确认；其他题目跳入该题的目标仍有效。

### 4.5 复制问卷

复制生成新的草稿和访问链接，不复制回答，不继承发布状态。题目内部 ID 重新生成，跳转目标同步映射到新题号，版本来源保持不变。

## 五 共享与统计权限

题目作者可以按用户名共享，也可以允许所有登录用户选用。被共享者可以选用各版本，或复制为自己的独立题目后修改，不能修改原题的版本、共享设置或其他用户的题库。

题目作者可以查看该题在所有引用问卷中的使用位置，以及该题的匿名跨问卷统计。被共享者仅能查看自己问卷中的该题统计。此规则在共享界面中明确说明；统计不展示填写者账号，也不开放其他题目或他人的问卷编辑页面。

取消共享只阻止后续访问和选用，不删除已经加入问卷的快照。因此他人已完成的问卷仍可以正常填写和统计。

## 六 统计实现与口径

原有按问卷统计继续保留。新增跨问卷统计先定位某一版本被引用的“问卷 ID 与本地题目 ID”组合，然后使用 MongoDB 聚合处理相应答案。

查询必须匹配这两个字段的组合，不能把所有问卷 ID 和所有题号分别拼接，否则可能将另一份问卷中同名题号的无关答案混入统计。

| 题型 | 统计结果 |
|---|---|
| 单选 | 每个选项次数，包含未被选择的选项 |
| 多选 | 拆分数组后分别累计各选项次数 |
| 文本 | 展示相应题目版本的全部文本回答 |
| 数字 | 回答数、平均值、最小值、最大值、各数值出现次数及全部数值 |

不同版本分别统计。例如“年龄（周岁）”与“年龄（月）”不能直接混算；查看全部版本时，也展示独立的版本统计卡片。

回答数以实际回答条目计数，不按账号跨问卷去重。同一人在不同问卷作答、或同一版本在一份问卷中出现多次时，各次合法回答分别计入。

## 七 第一阶段数据迁移

应用启动时自动执行幂等迁移，为没有来源字段的旧题目建立初始系列和 v1 版本，并加入该用户的默认题库。

迁移只补充来源元数据，保留原题干、选项、规则、本地题号、发布状态和已有回答。重复启动不会再次生成同一批版本。两个独立创建但题干相同的旧题目不会被自动合并，避免将含义不同的数据错误混算。

第一阶段的提交包仍单独保留，第二阶段的代码在原项目中继续演进。

## 八 启动与使用

### 8.1 启动

依赖文件未增加新的第三方库。已有环境可在原项目目录继续执行：

```powershell
python -m pip install -r requirements.txt
python run.py
```

MongoDB 需要先启动。原 Windows 示例路径为：

```powershell
& "D:\mongo\bin\mongod.exe" --dbpath "D:\mongo\data\db"
```

浏览器打开 http://127.0.0.1:8000。默认数据库仍为 survey_system，配置模板为 env.example；复制为 .env 后可调整连接。gitignore.txt 为可网页上传的忽略规则模板，恢复为 .gitignore 后由 Git 使用。

### 8.2 题库操作流程

1. 登录后点击顶部“题目库”或“管理题库”。
2. 新建题库分类，再创建单选、多选、文本或数字题。
3. 在题目详情中设置共享用户名。
4. 编辑草稿问卷，通过“从题库选题”选择明确的版本。
5. 需要改题时点击“基于此版本修改”，保存为新版本。
6. 在历史列表中查看父版本、恢复来源和使用位置。
7. 使用“恢复此版本为新版本”恢复内容；旧问卷继续使用原版本。
8. 点击“跨问卷统计”，查看不同问卷中的同一版本回答。
